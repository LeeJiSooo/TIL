## 정의와 위치

클라이언트의 요청 을 대신 받아 백엔드 서버(WAS)로 전달하고, 서버의 응답을 다시 클라이언트에게 돌려주는 중개(대리인)서버이다.

- 리버스의 의미:
    - 포워드 프록시 : 클라이언트 앞에 서서 클라이언트를 대리함(회사 사내망에서 외부 인터넷 접근 통제/캐싱)
    - 리버스 프록시 : 서버 앞에 서서 서버를 대리한다. 클라이언트는 뒤에 실제 백엔드 서버가 몇 대가 있는지 알지 못하며, 오직 리버스 프록시만 바라본다.
- 특정 제품이 아닌 역할의 개념 :
    - Nginx, Apache, Caddy같은 웹 서버 소프트웨어를 활용하여 리버스 프록시 역할을 수행하도록 구성한다.

## 왜 서버 앞에 리버스 프록시를 두는가?

리버스 프록시 없이 사용자 브라우저가 백엔드 서버(스프링 부트 등)에 직접 붙으면 다음과 같은 비효율과 보안 문제가 발생한다.

1. 실제 백엔드 서버의 IP/포트 은닉(보안) :
    
    외부에 노출되는 주소는 오직 리버스 프록시 하나이다. 내부 WAS 서버들의 실제 IP나 8080포트 등 내부 구조가 외부에 드러나지 않아 해킹 위험이 줄어든다.
    
2. 공통 관심사의 일괄 처리 :
    
    SSL/TLS암호화(HTTPS)오프로딩 : 서버가 여러 대일 때 각 백엔드 서버가 일일이 SSL 인증서를 관리하고 암복호화 연산을 하면 CPU 낭비가 심하다. 이를 리버스 프록시 한 곳에서 전담하여 처리한다.
    
    캐싱 및 압축 : 자주 들어오는 정적 파일이나 응답을 리버스 프록시가 미리 캐싱해 두어 백엔드 서버의 부하를 덜어준다.
    
3. 유연한 아키텍처 확장(단일 진입점 제공) :
    
    서비스가 성장하여 백엔드 서버를 추가/교체하거나 주소를 바꾸더라도, 클라이언트는 자신이 알던 엔드포인트 주소를 바꿀 필요가 전혀 없다.
    
    요청 URL 경로에 따라 적절한 백엔드 서버로 보내는 라우팅 및 로드 밸런싱 역할을 한다.
    

## 트래픽 전달 경로 & 502 Bad Gateway

Route 53을 통해 리버스 프록시의 IP를 알아낸 브라우저가 실제 요청을 보낼 때의 전달 순서이다.

1. 클라이언트 → 리버스 프록시 요청
    
    HTTP 80 / HTTPS 443
    
    브라우저가 리버스 프록시의 공개 퍼블릭 IP/포트로 요청을 보낸다.
    
2. 전달 규칙 확인
    
    리버스 프록시는 들어오는 도메인 이름이나 경로를 확인하여, 준비된 라우팅 규칙에 따라 어떤 백엔드 서버로 보낼지 결정한다.
    
3. 리버스 프록시 → 백엔드(WAS)전달
    
    설정된 규칙의 백엔드 주소 및 포트로 요청을 넘긴다.
    
4. 백엔드 처리 → 프록시 거쳐 클라이언트로 응답
    
    백엔드가 처리한 결과를 리버스 프록시가 받아 클라이언트로 다시 전달한다.
    

**502 Bad Gateway**

요청이 리버스 프록시(Nginx)까지는 성공적으로 잘 도착했는데, 그 뒤에 있는 백엔드 서버(WAS)가 게이트웨이 역할을 하는 프록시에게 올바른 응답을 주지 못했다는 뜻.

원인 추적 포인트 :

1. 스프링 부트(WAS)애플리케이션 프로세스가 꺼져 있거나 안 떠있는 경우
2. Nginx의 설정 파일에 적어둔 백엔드 주소/포트 번호가 틀린 경우
3. 백엔드 서버로 가는 내부 네트워크/보안 그룹 경로가 막혀 있는 경우
4. 백엔드 서버에 부하가 걸려 제때 응답을 주지 못한 경우

Web Server와 WAS 차이점

| **구분** | **Web Server (웹 서버)** | **WAS (Web Application Server)** |
| --- | --- | --- |
| **주요 역할** | 정적 콘텐츠(HTML, CSS, JS, 이미지) 제공 및 **리버스 프록시 역할** | 동적 콘텐츠(비즈니스 로직, DB 조회) 처리 |
| **대표 예시** | Nginx, Apache | Apache Tomcat, Netty |
| **특징** | 요청을 가장 먼저 받아 처리하며, 비즈니스 로직이 필요한 동적 요청만 WAS로 이관함 | 비즈니스 로직 연산이 필요하므로 CPU/메모리 자원을 상대적으로 많이 사용함 |

## 정리

- 리버스 프록시는 서버 앞단에 위치하고 클라이언트 요청을 대신 받아서 하나 이상의 백엔드 서버로 전달하고, 응답을 다시 돌려주는 중개 구조이다.
- 왜 두는가? 외부에 열리는 진입점을 하나로 모으고, 요청을 여러 서버로 나누고, 암호화 통신 하는 것도 한 자리에서 정리해주고 자주 나가는 응답이 있다라고 하면 캐싱하거나 압축도 해준다.
- 502 Bad Gateway : 리버스 프록시까지는 요청이 닿았으나, 뒤쪽 WAS와의 통신이 실패했음을 의미하는 대표적인 상태 코드
