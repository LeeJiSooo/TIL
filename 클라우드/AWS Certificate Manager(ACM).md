## SSL/TLS 인증서의 정의와 역할

- SSL/TLS : 인터넷상에서 클라이언트와 서버 간의 데이터를 암호화하여 주고받는 통신 규약
- 인증서의 핵심 역할 : 서버가 통신 시작 시 사용자에게 주는 ‘디지털 신분증’
    1. 신원 증명(도메인 소유 확인) : 내가 접속한 사이트가 진짜 my-service.com이 맞는지 증명
    2. 기밀성 및 무결성(데이터 암호화) : 전송되는 데이터(비밀번호, 결제 정보 등)를 암호화하여 중간에 해커가 도청하거나 위변조하는 것을 차단

**CA(인증 기관)와 신뢰 검증 방식**

1. 서버가 내민 인증서에는 도메인 이름과 공인된 인증 기관(CA)의 디지털 서명이 적혀있다.
2. 사용자의 브라우저는 전 세계적으로 검증된 CA목록을 내장하고 있다.
3. 브라우저가 서명을 검증하여 신뢰하는 CA가 발급한 것이 맞으면 주소창에 자물쇠를 띄우고, 아니면 경고창을 띄운다.
4. 도메인 소유권 확인 절차 : CA는 인증서를 그냥 발급하지 않고, 신청자가 해당 도메인의 주인이 맞는지 DNS설정(CNAME 레코드 추가 등)을 바꿔보라고 요구한 뒤 소유권이 확인되어야만 인증서를 발급해준다.

## ACM

AWS 인프라에서 사용되는 SSL/TLS 인증서를 손쉽게 생성, 관리, 배포, 갱신해주는 관리형 서비스이다.

**인증서가 실제 연결되는 위치(ELB연동)**

ACM에서 발급받은 인증서는 EC2 서버 안으로 직접 다운로드하여 넣지 않고, ELB에 붙여서 사용한다.

```jsx
[사용자 브라우저] ──(HTTP 요청)──► [ Route 53 ] (ELB 도메인 전달)
                                        │
                                        ▼
                           [ ELB (443 HTTPS 리스너) ] ◄── ACM 인증서 연결
                                        │ (TLS 암호화 연결 완료 & 복호화)
                                        ▼ (VPC 내부망 통신 - HTTP:8080)
                           [ EC2 인스턴스 (스프링) ]
```

1. Route 53 도메인 조회
    
    사용자가 브라우저 주소창에 도메인을 치면 Route 53이 ELB의 주소를 전달한다.
    
2. ELB 진입점에서 TLS연결
    
    사용자 요청이 ELB의 443 포트에 도착하면, ELB가 ACM에서 연동해둔 SSL/TLS 인증서를 브라우저에게 내민다. 브라우저가 자물쇠를 확인화여 암호화 통신을 시작한다.
    
3. 내부 VPC 통신 및 백엔드 전달
    
    ELB가 암호화된 요청을 복호화한 뒤, VPC 내부망을 통해 뒤쪽에 있는 EC2인스턴스(WAS)로 넘겨준다.
    

**리전 단위 자원** : ACM인증서는 리전 단위 자원이다. (서울 리전의 ALB에 연결하려면 ACM인증서도 서울 리전에서 발급받아야 한다.)

**퍼블릭 인증서 vs 프라이빗 인증서**

| **구분** | **퍼블릭 인증서 (Public Certificate)** | **프라이빗 인증서 (Private Certificate)** |
| --- | --- | --- |
| **발급 주체** | 브라우저가 이미 신뢰하는 공인 CA (Amazon 등) | 조직/기업 내부에서 자체적으로 세운 사설 CA |
| **주요 사용처** | 인터넷에 공개된 **웹사이트, 외부 공개 API** | 회사 **사내망 내부 서비스, 시스템 간 내부 통신** |
| **특징** | 누구나 접속해도 브라우저에 경고 없이 자물쇠 가 뜸. **ACM 퍼블릭 인증서는 무료** | 일반 브라우저 신뢰 목록에 없으므로, **사내 기기/서버에 사설 CA를 신뢰하도록 별도 설정 필요**. |

## 정리

- Route 53이 도메인 이름을 진입점에 연결하고, 사용자 요청이 ELB에 도착하면 TLS 연결이 맺어지고, 그때 사용되는 인증서가 ACM에 있는 인증서이다.
    - EC2안에 파일 복사해서 넣지 않아도 사용자가 인프라랑 만나는 진입점에서 인증서가 연결된다.
- 인증서는 도메인이 맞다는 신원확인이랑 전송 내용의 기밀성, 무결성을 제공하는 역할을 하고 ACM 인증서를 만들고, 소유권을 확인하고 보관하고 갱신하고 지원하는 서비스에 배포하는 역할을 한다.
