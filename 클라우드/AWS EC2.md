## 정의

사용자가 필요에 따라 가상 서버를 쉽게 생성, 구성, 관리할 수 있도록 AWS가 제공하는 클라우드 가상 서버 서비스

→ 내 애플리케이션을 배포할 컴퓨터 한 대를 AWS 데이터 센터에서 빌려 쓰는 것

- EC2(Elasitc Compute Cloud) : 가상 서버를 만들어주는 창구 / 서비스 이름
- 인스턴스 : 그 창구를 통해 생성되어 클라우드 어딘가에서 실제로 돌아가고 있는 가상 서버 ‘한 대’(OS, CPU, RAM, 저장소를 갖춘 독립된 컴퓨터)
- 워크로드 : 서버나 애플리케이션이 감당해야 하는 일의 양이나 종류

EC2이름에 담긴 의미

- Elastic(탄력적인) : 트래픽 유무에 따라 인스턴스를 자유롭게 늘리거나 줄일 수 있다.
- Compute(계산 자원) : 원하는 CPU, 메모리, 네트워크 성능을 갖춘 가상 컴퓨터를 즉시 확보
- Cloud(클라우드/온디맨드) : 인터넷을 통해 필요할 때 즉시 만들고, 쓴 만큼만 비용을 내는 방식(On-Demand)

## 왜 물리 서버 대신 EC2를 쓰는가? (On-Premises vs Cloud)

| **구분** | **물리 서버 (온프레미스 / IDC)** | **클라우드 가상 서버 (AWS EC2)** |
| --- | --- | --- |
| **서버 확보 시간** | 용산 가거나 구매 신청 후 수일~수주 소요 | 클릭 몇 번 또는 명령어로 **수분 내 즉시 확보** |
| **트래픽 대응** | 트래픽 폭주 시 장비를 직접 사서 추가 설치해야 함 | 클릭 몇 번으로 스케일 아웃(인스턴스 추가) 가능 |
| **비용 구조** | 사용하지 않더라도 초기 구매/구축 비용 막대함 | **온디맨드 요금제** (쓴 시간/자원만큼만 후불 지불) |
| **유연성** | CPU/RAM 스펙 변경이 어렵거나 불가능 | 애플리케이션 성격에 맞춰 인스턴스 타입 자유롭게 변경 |

## EC2 인스턴스 수명 주기 & 비용

인스턴스는 시작 → 실행 → 중지 → 종료라는 수명 주기를 거치게 된다. 단계별로 비용 발생 여부와 데이터/IP변화를 정확히 알아야 예상치 못한 요금 폭탄이나 접속 장애를 막을 수 있다.

```json
[시작 (Launch)] ──► [실행 (Running)] ──► [중지 (Stop)] ──► [종료 (Terminate)]
 (초기 설정/부팅)     (정상 작동/요금 청구)   (컴퓨터 OFF/EBS비용만)   (서버 영구 삭제)
```

| **수명 주기 단계** | **상태 설명** | **컴퓨팅 요금 (CPU/RAM)** | **저장소 요금 (EBS)** | **핵심 주의사항 & 실무 팁** |
| --- | --- | --- | --- | --- |
| **시작 (Launch)** | OS 및 초기 설정을 구성하고 켜지는 부팅 단계 | 발생 시작 | 발생 | 만들어서 켜지는 순간부터 요금이 부과되기 시작함. |
| **실행 (Running)** | 서버가 돌아가며 사용자 요청을 정상 처리하는 상태 | **정상 청구** | **정상 청구** | 우리가 목표로 하는 일반적인 운영 상태. |
| **중지 (Stop)** | 서버 본체를 잠깐 **꺼둔 상태**  | **발생 안 함** | **지속 발생** | 꺼둬도 가상 하드디스크인 **EBS(Elastic Block Store)** 비용은 계속 나감. 데이터는 유지됨. |
| **종료 (Terminate)** | 서버를 **영구히 삭제**하는 단계 | **발생 안 함** | 삭제됨 (선택) | 서버와 본체가 완전히 사라짐. 설정에 따라 붙어있던 EBS 디스크도 함께 삭제되어 복구 불가. |

가장 많이 터지는 이슈

- 중지 후 재시작 시 퍼블릭 IP 변경 문제 :
    - EC2인스턴스를 중지했다가 다시 켜면 기본 퍼블릭 IP가 바뀐다.
    - IP가 바뀌면 도메인 연결, DB접속 연결, 보안 그룹 IP 등록 등이 한꺼번에 틀어진다.
    - 서버를 껐다 켜도 주소가 바뀌지 않도록 고정 퍼블릭 IP(탄력적 IP)를 할당해서 붙여줘야 한다.
- EBS(Elastic Block Store)개념 :
    - 인스턴스가 ‘컴퓨터 본체’라면, EBS는 거기 꽂혀 있는 ‘외장 하드디스크’
    - 본체(EC2)를 꺼두더라도, 하드디스크(ESB)에 내 데이터가 보관되어 있으므로, 하드디스크 비용은 계속 청구된다.

→ 중지해도 EBS디스크 요금은 청구되며, 재시작 시 퍼블릭 IP가 바뀌므로 탄력적 IP설정이 필요하다. 완전히 삭제할 때는 종료를 해야한다.

## 용어 정리

- EC2 : 클라우드에서 가상 서버를 빌려 쓰는 AWS 서비스
- 인스턴스 : EC2로 띄운 독립된 가상 컴퓨터 한 대
- EBS : EC2 인스턴스에 장착하는 가상 하드디스크

## 정리

- EC2는 물리 장비 사지 않고 클라우드에서 필요할 때 가상 서버를 만들고 관리할 수 있게 해주는 서비스이다.
- 그렇게 만들어진 서버 한대가 인스턴스며, 우리가 만든 애플리케이션은 그 인스턴스 위에서 사용자 요청을 처리한다.
- 트래픽 오르거나 내려도 유연하게 처리된다. → 쓴만큼 비용이 나감
- 수명주기 - 시작, 실행, 중지, 종료가 있다. 중지해도 EBS볼륨에서 비용은 계속 나가고 껐다가 켜면 퍼블릭 IP가 바뀌어서 고정해야한다.
