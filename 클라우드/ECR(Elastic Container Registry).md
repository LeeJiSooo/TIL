## 설명할 수 있어야 하는 것

- ECR이 일반적인 레지스트리와 같은 부분은 무엇이고 AWS 안에서 추가로 책임지는 부분은 무엇인지
- 이미지 주소가 계정, 리전, 레포지토리, 태그로 어떻게 좁아지는지
- 이미지를 주고 받는 과정에서 권한과 네트워크가 각각 어디에 적용되는지

## 정의와 핵심 개념

AWS 계정 내에서 컨테이너 이미지를 안전하게 저장, 버전 관리, 접근 제어, 취약점 스캔까지 자동으로 처리해주는 완전관리형(Fully Managed)프라이빗 레지스트리

관전관리형의 이점

- 개인이 프라이빗 레지스트리를 직접 서버에 구축하면 디스크 용량 증설, OS 보안 패치, 서버 장애 복구 등을 직접 다 해야 한다.
- ECR을 쓰면 저장소 관리, 자동 백업, 디스크 확장을 AWS가 알아서 다 해주므로 개발자는 이미지 push/pull에만 집중하면 된다.

프라이빗 기본값 : ECR은 기본적으로 외부 공개가 아닌 AWS IAM을 통한 인증을 거친 대상만 접근 가능하다.

## ECR의 자원 범위 & 이미지 URI 구조

ECR은 리전 단위 서비스이며, 이미지 주소(URI)를 보면 계정, 리전, 저장소, 버전을 한눈에 알 수 있다.

```
{계정ID}.dkr.ecr.{리전}.amazonaws.com/{리포지토리}:{태그}
```

```
[ 이미지 URI 예시 ]
123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/my-spring-app:1.0.0
 └────┬────┘        └──────┬──────┘              └──────┬──────┘└─┬─┘
      │                    │                            │        │
   AWS 계정 ID          서울 리전                     리포지토리    태그 (버전)
 (다른 계정과 구분)   (이미지 물리 저장소)            (앱 단위 저장소)
```

- 계정 ID : 내 AWS 계정 고유 번호
- dkr.ecr : 도커 엔진과 통신하는 ECR 전용 API 엔드포인트
- 리포지토리 : 애플리케이션 단위의 저장 공간(my-spring-app)
- 태그 : 동일한 앱의 버전을 나타내는 식별자(예 : 1.0.0, latest)

## ECR권한 및 보안 메커니즘(IAM 연동)

ECR은 별도의 레지스트리 비밀번호를 사용하지 않고, AWS IAM 자격 증명으로 접근을 통제한다.

**인증 및 토큰 발급 흐름(EC2 → ECR)**

1. IAM Role(역할) 연결 : EC2인스턴스에 ECR 접근 권한이 담긴 IAM Role을 연결해둔다. (비밀번호를 하드코딩하지 않는다.)
2. 임시 인증 토큰 요청 : EC2의 도커 데몬이 AWS CLI/SDK를 통해 ECR에게 유효기간 12시간짜리 임시 인증 토큰을 요청해 받아온다.
3. 도커 로그인 & 이미지 가져오기 : 받아온 임시 토큰으로 docker login을 수행한 뒤, 안전하게 이미지를 pull 받아온다.

## ECR 전용 IAM 정책 문법

이미지를 가져오기만 하는 서버(EC2)에게 올리는 권한까지 주면 안 되므로, 최소 권한의 원칙에 맞춰 IAM정책을 작성해야 한다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowGetAuthToken",
      "Effect": "Allow",
      "Action": "ecr:GetAuthorizationToken", // 1. 로그인에 필요한 임시 인증 토큰 요청 권한
      "Resource": "*"                         // 레지스트리 전체 단위 작업이므로 * 로 지정
    },
    {
      "Sid": "AllowPullImagesOnly",
      "Effect": "Allow",
      "Action": [
        "ecr:BatchGetImage",                  // 2. 이미지 매니페스트 읽기
        "ecr:GetDownloadUrlForLayer"          // 3. 이미지 레이어 다운로드 (Push 권한은 없음)
      ],
      "Resource": "arn:aws:ecr:ap-northeast-2:123456789012:repository/my-spring-app" // 4. 특정 리포지토리로 범위 축소
    }
  ]
}
```

## 왜 써야 하는가?

- 완전관리형의 편의성 : 저장 공간 증설, 가용성 유지, 보안 패치 등의 백엔드 인프라 관리를 AWS에 위임한다.
- AWS 인프라 서비스와 완벽한 통합 : EC2, ECS, EKS, AWS Fargate등 컨테이너 실행 환경이 별도의 복잡한 세팅 없이 IAM Role만으로 ECR의 이미지를 즉시 가져와 실행 가능하다.
- 이미지 보안 스캔 : 올린 이미지 안에 알려진 취약점이나 보안 구멍이 있는지 자동으로 검사하여 결과 리포트를 제공한다.
    - 네트워크 및 비용 최적화 : 동일한 AWS 리전/VPC 내부에서 이미지를 다운로드하므로, 외부 인터넷망을 거쳐서 받아오는 것보다 다운로드 속도가 압도적으로 빠르고 안정적이다.

## 정리

- ECR은 컨테이너 이미지를 등록해두고 인증된 대상에만 내주는 완전 관리형 프라이빗 레지스트리이다. → 레지스트리가 AWS 안에 있다.
- 자원 범위는 리전단위이다. 계정이랑 리전이 정해지면 그 안에 레지스트리가 있고, repo로 어플리케이션 나누고 태그로 버전 구분을 한다.
- 접근 권한 관리를 IAM의 정책을 따라가면서 관리가 된다.
- IAM 정책을 통해 서버(EC2)에는 **Pull 권한(BatchGetImage, GetDownloadUrlForLayer)만 부여**하고, 올리는 권한(Push)은 CI/CD 파이프라인에만 제한적으로 부여함 → 권한 최소화
