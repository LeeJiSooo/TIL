## 보안 그룹의 정의와 위치

클라우드 환경에서 가상 서버 인스턴스나 가상 네트워크 인터페이스에 대한 네트워크 트래픽을 제어하는 가상 방화벽이다.

→ 방화벽은 규칙에 따라 통과시킬 트래픽과 막을 트래픽을 구분하는 장치인데, 이를 물리 장비가 아니라 클라우드 설정으로 제공하므로 ‘가상 방화벽’이라 부른다.

인스턴스의 네트워크 인터페이스 바로 옆에 붙어있다.

→ AWS 네트워크 계층에서 동작하기 때문에, 외부 요청은 실제 서버에 도달하기 전에 이 보안 그룹을 반드시 먼저 통과해야 한다.

## 규칙 구성 요소(소스, 프로토콜, 포트)

보안그룹은 기본적으로 “화이트리스트”방식으로 동작한다. 즉, 기본값은 ‘모두 차단’이며, 규칙에 명시적으로 허용한 트래픽만 통과할 수 있다. 이 허용 규칙은 3가지 조합으로 만들어진다.

- 소스 : 트래픽이 “어디서 출발했는가?” (출발지 IP 대역 또는 다른 보안 그룹 ID)
- 프로토콜 : “어떤 방식으로 통신하는가?” (예 : TCP, UDP)
- 포트 : “서버 안의 어떤 프로그램으로 가는가?”
    - 한 대의 서버 안에는 웹서버, DB 등 여러 프로그램이 동시에 돌 수 있다. 포트는 그중 어떤 프로그램으로 가야 하는지 가리키는 방 번호와 같다.
    - *주요 포트 예시:* HTTP(`80`), HTTPS(`443`), SSH 원격접속(`22`), 로컬 스프링 부트(`8080`) 등

## 인바운드 vs 아웃바운드, Stateful(상태 저장)

트래픽의 방향은 크게 두 가지로 나뉘고, 보안 그룹은 Stateful(상태 저장형)로 동작한다.

- 인바운드 : 바깥에서 인스턴스 내부로 들어오는 트래픽
- 아웃바운드 : 인스턴스 내부에서 바깥으로 나가는 트래픽

**Stateful(상태저장) 방화벽이란?**

외부 사용자가 요청을 보내서 인바운드 규칙을 통과해 서버로 들어오면, 보안 그룹은 이 요청을 기억(상태 저장)하고 있다. 따라서 서버가 처리 후 응답을 돌려줄 때(아웃바운드), 별도의 아웃바운드 규칙이 없어도 자동으로 응답 패킷을 내보내 준다.

- 즉, 요청과 응답을 ‘한 쌍’으로 묶어서 처리하기 때문에, 개발자는 인바운드 규칙만 잘 신경쓰면된다. (정상적으로 들어온 요청에 대한 응답이 아웃바운드 규칙에 막혀 사용자가 화면을 못 보는 일은 없다.)
- 네트워크 ACL(NACL)은 Stateless(상태 비저장)라서 나가는 응답 규칙도 일일이 수동으로 열어줘야 했지만, 보안 그룹은 Stateful이라 알아서 해준다.

**인스턴스 위에 웹 서버를 띄우고, 외부에는 웹 접속만 열어주고 싶을 때의 인바운드 규칙**

| **유형** | **프로토콜** | **포트 범위** | **소스 (출발지)** | **설명 및 실무 팁** |
| --- | --- | --- | --- | --- |
| **HTTP** | TCP | 80 | `0.0.0.0/0` | 일반 웹 페이지 요청 창구. 전 세계 모든 IP 주소를 뜻하므로 누구나 접속 가능하게 넓게 오픈. |
| **HTTPS** | TCP | 443 | `0.0.0.0/0` | 암호화된 안전한 웹 요청 창구. 마찬가지로 공개 서비스이므로 전 세계에 오픈. |
| **SSH** | TCP | 22 | `(신뢰하는 IP 대역)` | 관리자가 터미널로 접속해 서버 내부 명령을 실행하는 관리 통로. **절대 `0.0.0.0/0`으로 열면 안 됨.** 내 컴퓨터 IP나 회사 IP 대역으로 좁혀야 안전함. |

## 정리

- 보안 그룹의 위치는 인스턴스 네트워크 바로 옆에 붙어 있는 검문소 같은 개념이다. AWS 네트워크 계층에서 동작하기 때문에 요청은 서버에 도달하기 전에 먼저 검문소를 지나간다.
- 역할은 소스, 프로토콜, 포트 기준으로 인바운드랑 아웃바운드 트래픽을 거른다. 인바운드는 기본적으로 막혀있고 명시적으로 허용하는 것만 통과하낟.
- 보안그룹은 stateful방화벽이라서 허용된 요청에 대한 응답은 따로 열지 않아도 된다. 인바운드만 신경쓰면 된다.
