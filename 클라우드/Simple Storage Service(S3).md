## 정의

대규모 비구조화 데이터를 객체 단위로 인터넷상에 안전하게 저장하고 관리하는 확장 가능한 클라우드 스토리지 서비스

구성 요소

1. 버킷 : 데이터를 담는 최상위 컨테이너(폴더의 최상위 개념)
    
    → 버킷 이름은 전 세계 AWS 모든 계정을 통틀어서 유일해야 한다.
    
2. 객체 :  S3에 저장되는 실제 데이터 파일과 그 파일의 부가 정보의 집합
3. 키 : 버킷 안에서 특정 객체를 식별하는 전체 파일 경로 이름

## 왜 DB나 EC2 디스크 대신 S3를 쓸까?

서비스에 이미지나 파일 업로드 기능이 들어갈 때, 이를 어디에 저장하느냐에 따라 백엔드 성능과 운영 부담이 갈린다.

RDB(RDS)에 이미지 직접 저장

- MB짜리 이미지 파일이 RDB 행마다 들어가 백업/복구 시간이 증가한다.
- 조건 검색 중심의 RDB가 무거워져서 일반 게시글 목록 조회까지 속도가 느려진다.

EC2 서버 디스크(static 폴더)에 직접 저장

- EC2 인스턴스 용량이 채워지는지 개발자가 매번 모니터링 해야한다.
- Auto Scaling으로 EC2가 삭제되면 사용자 프로필 사진도 함께 증발한다.
- 이미지 다운로드 트래픽을 EC2가 다 감당해야 해서 서버 CPU/RAM 낭비가 심해진다.

권장 : AWS S3 + RDB 연동

- 이미지 파일 자체는 S3에 올리고, RDB파일의 주소 문자열(S3문자열 또는 Object Key)만 저장한다.
- 게시글 테이블은 가볍게 유지된다.
- 클라이언트가 이미지를 볼 때 S3에서 직접 꽂아서 받아가므로, 백엔드 서버는 이미지 전송 부하에서 완전히 자유로워진다.

## 네트워크 위치의 차이

| **구분** | **AWS RDS (데이터베이스)** | **AWS S3 (객체 스토리지)** |
| --- | --- | --- |
| **위치** | **VPC 내부** (Private Subnet) | **VPC 외부** (AWS 리전 단위 서비스) |
| **접속 방식** | DB 커넥션 생성 (엔드포인트) | **HTTPS 기반의 REST API 호출** (AWS SDK) |
| **차단/허용 주체** | **보안 그룹 (Security Group)** 인바운드 규칙 | **IAM 정책** 및 **S3 버킷 정책 (Bucket Policy)** |
| **에러 원인** | 주로 네트워크 경로 막힘 또는 포트(3306) 차단 | 주로 **권한(Access Denied) 문제** (IAM / 버킷 정책) |

## S3 보안 관리 & 버킷 정책

S3는 외부 인터넷에 노출되는 HTTP엔드포인트를 가지므로, 권한 설정을 잘못하면 데이터 유출 및 무한 다운로드로 인한 요금 폭탄이 발생할 수도 있다.

퍼블릭 버킷 정책 문법

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowAppRoleReadObjects",
      "Effect": "Allow", // Allow: 허용, Deny: 차단
      "Principal": { "AWS": "arn:aws:iam::123456789012:role/app-server-role" }, // 누구에게? (특정 IAM 역할)
      "Action": ["s3:GetObject"], // 어떤 작업을? (객체 읽기/다운로드)
      "Resource": "arn:aws:s3:::my-app-uploads/*" // 어떤 대상에? (my-app-uploads 버킷 내 전체 객체)
    }
  ]
}
```

보안을 지키는 법

1. 버킷 퍼블릭 액세스 차단 : 기본적으로 버킷 전체를 외부에 무분별하게 퍼블릭으로 열어두지 않는다.
2. CloudFront(CND)연동 : S3의 원본 주소를 외부에 노출하지 않고, CND을 통해 캐싱하여 안전하게 파일 전송 및 비용을 절감한다.
3. 고아 객체 주기적 처리 : 프론트에서 S3업로드는 성공했으나 백엔드 DB저장 실패 시 발생할 수 있는 ‘고아 파일’을 주기적으로 스케줄러를 통해 저장하는 로직을 고려한다.

## 정리

- S3는 이미지, 로그, 백업파일처럼 데이터 파일을 객체 단위로 보관하는 스토리지 서비스
- 버킷이라는 컨테이너 안에 객체를 두고 키로 그 객체를 찾는다.
- 위치는 VPC 안에 있는게 아니라 리전 단위로 있고 우리가 설정한 네트워크 바깥에서 API 요청하는 것처럼 가져오고 처리한다.
- S3 쓰는건 용량 걱정 없이 저장할 수 있고 내구성이랑 가용성이 좋다. 데이터라고하는걸 컴퓨팅 자원에서 떼어놓고 볼 수 있어서 좋다.
