## 정의와 필요성

AWS 리소스에 대한 사용자 인증과 권한 관리를 제공하는 계정 단위의 글로벌 서비스

리전에 종속되지 않고 계정 전체에 적용된다.

존재 이유(최소 권한 원칙) : 회사에서 AWS를 쓸 때 비용이나 보안 문제가 생기지 않도록, 모든 사람에게 모든 권한을 주면 안됨

역할 분담의 이해 :

- IAM : “이 인스턴스를 종료할 권한이 있는가?”(작업 권한 판단)
- VPC / 보안 그룹 : “이 인스턴스에 네트워크로 접속할 수 있는가?”(네트워크 경로 및 포트 제어)

→ 접속은 되는데 작업이 거부되면 IAM을 봐야하고, 애초에 접속이 안 되면 VPC/보안 그룹을 봐야 한다.

## 인증 vs 인가

AWS입장에서는 콘솔 버튼 클릭, 터미널 명령, 애플리케이션 코드 모두 똑같은 ‘API 요청’으로 인식한다. IAM은 이 API 요청이 처리되기 직전에 끼어드는 관문 역할을 한다.

- 인증 : 로그인/비밀번호 확인, 애플리케이션의 자격 증명 서명 확인 등을 통해 신원을 검증하는 단계
- 인가 : 신원이 확인된 주체가 요청한 작업(EC2종료)을 수행할 자격이 있는지 판단하는 단계. → 로그인 성공과 EC2 종료 권한은 별개의 문제임

| **구성 요소** | **정의** | **Windows 비유** | **핵심 특징** |
| --- | --- | --- | --- |
| **사용자 (User)** | AWS 리소스에 접근하는 개별 계정 | 개별 사용자 계정 | 사람당 하나씩 매핑되는 개별 신원. |
| **그룹 (Group)** | 사용자들을 묶은 집합 | 사용자 그룹 (Administrators 등) | **권한을 담아두는 상자.** 10명의 백엔드 개발자 권한을 바꿀 때, 그룹 하나만 고치면 되므로 관리가 편해짐. |
| **역할 (Role)** | 임시로 권한을 위임하는 개념 | "관리자 권한으로 실행" | 사람뿐만 아니라 AWS 서비스(EC2 등)도 넘겨받아 사용함. 유효 기간이 짧은 **임시 자격 증명** 발급. |
| **정책 (Policy)** | 권한 규칙을 규정한 문서 | 파일/폴더 접근 권한 설정 | 무엇을 할 수 있는지 명시한 JSON 문서. 정책이 없으면 사용자는 로그인해도 아무것도 못 함. |

**역할(Role)이 왜 중요할까?**

EC2에서 돌아가는 애플리케이션이 S3에 파일을 저장해야할 때, 사람이 쓰는 고정 자격 증명(Access Key)을 서버 안에 텍스트 파일로 저장해 두면 유출 위험이 크다.

대신 EC2에 ‘역할’을 부여하면, 애플리케이션이 실행 중에 알아서 만료되는 임시 자격 증명을 받아 안전하게 S3를 호출할 수 있다. → 코드에 자격 증명이 남지 않아서 깔끔하다.

## 정책 문서 구조

1. 일반 권한 정책(무엇을 할 수 있는가?)

```json
{
  "Version": "2012-10-17", // 문법 버전 (고정값)
  "Statement": [
    {
      "Effect": "Allow",     // Allow(허용) 또는 Deny(거거부)
      "Action": "s3:GetObject", // 허용할 구체적인 AWS API 작업 명시
      "Resource": "arn:aws:s3:::project-photos/*" // 권한이 미치는 대상 리소스(ARN 고유 식별자)
    }
  ]
}
```

이 정책을 가진 주체는 `project-photos`라는 S3 저장 공간 안의 파일을 읽는 작업(`GetObject`)만 할 수 있음. (`*`를 쓰면 모든 대상이 범위에 들어옴)

1. 신뢰 정책(누가 이 역할을 쓸 수 있는가?)

역할(Role)에는 "이 역할을 아무나 가져가면 안 되니까, 누가 넘겨받을 수 있는지"를 정하는 정책이 하나 더 붙는다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "ec2.amazonaws.com" }, // 역할을 넘겨받을 주체 (여기선 EC2 서비스)
      "Action": "sts:AssumeRole" // 역할을 넘겨받는 행위(AssumeRole)를 허용
    }
  ]
}
```

사람이 아니라 **EC2 인스턴스 서비스**가 이 역할을 넘겨받아서 임시 자격 증명을 발급받을 수 있도록 허용한다.

```json
[주체의 API 요청] (사람, CLI, SDK 등 + 자격 증명 첨부)
       ↓
 1. 인증 (Authentication) : 자격 증명으로 신원 확인
       ↓
 2. 정책 수집 : 사용자 정책 + 그룹 정책 + 역할 정책을 전부 모음
       ↓
 3. 권한 평가 (IAM 관문) : 모아진 정책들을 분석하여 허용/거부 판단
       ↓
 ┌─────┴─────┐
 ↓           ↓
[허용(Allow)]   [거부(Deny)]
 ↓           ↓
실제 서비스 처리  권한 없음 오류 (Access Denied)
(EC2 종료 등)
```
