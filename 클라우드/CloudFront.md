## CloudFront와 CDN의 정의

- CDN(Content Delivery Network) : 전 세계에 분산된 서버 네트워크를 통해 이미지, 동영상, 정적 웹 콘텐츠(HTML, CSS, JS) 등을 사용자에게 지연 시간 없이 빠르고 안전하게 전달하는 콘텐츠 전송 전용 네트워크
- CloudFront : AWS가 제공하는 글로벌 저지연 CND 서비스

## 왜 S3만으로 안 되고 CloudFront가 필요한가?

S3 버킷 하나만 외부에 직접 공개해서 쓸 때 발생하는 결정적 한계 때문이다. 

1. 물리적 거리 및 지연시간 : S3버킷은 서울 리전이라는 특정 물리 위치에 묶어 있다. 남미나 유럽 사용자가 요청하면 태평양을 건너오느라 응답이 느려진다.
2. 원본 트래픽 몰림 및 비용 폭증 : 동일한 로고 이미지나 정적 파일을 전 세계 10만 명, 100만 명이 매번 S3에서 직접 다운로드하면, S3 부하 및 아웃바운드 데이터 전송 비용이 폭발한다.
3. 보안상 위험 : S3버킷을 직접 외부 인터넷 퍼블릭으로 전부 열어두어야 하므로, 버킷 주소가 노출되어 무단 접근이나 디도스 공격에 노출된다.

## 리전 자원 vs 글로벌 전역 자원

| **구분** | **AWS S3 (Origin)** | **AWS CloudFront (Distribution)** |
| --- | --- | --- |
| **자원 범위** | **리전 단위 자원** (예: 서울 리전) | **글로벌 전역 자원** (전 세계 적용) |
| **설정 단위** | 버킷  | **배포**  |
| **핵심 역할** | 데이터의 **원본 보관** | 전 세계 엣지 로케이션에 사본 캐싱 |

엣지 로케이션 : CloudFront가 컨텐츠 사본을 캐싱하기 위해 전 세계 주요 거점에 배치한 AWS의 분산 데이터 센터 네트워크

## 요청 처리 경로 : Cache Hit , Cache Miss

사용자가 도메인 주소를 입력했을 때, DNS가 알려주는 IP는 S3의 주소가 아닌 가장 가까운 CloudFront엣지 로케이션의 IP이다.

```json
[ 사용자 브라우저 ]
        │
        ▼ 1. 가장 가까운 CloudFront 엣지 로케이션에 요청 도착!
┌───────────────────────────────────────────────────────────┐
│                    CloudFront 엣지 로케이션                │
└─────────────────────────────┬─────────────────────────────┘
                              │
             ┌────────────────┴────────────────┐
             ▼ (캐시 있음)                       ▼ (캐시 없음)
	     [  Cache Hit ]                   [ Cache Miss ]
             │                                 │
             ├─► 2a. 엣지 사본 즉시 반환       ├─► 2b. 서울 S3(Origin)로 원본 요청
             │   (S3까지 요청 안 감!)          │   (VPC/인터넷)
             │                                 ├─► 3b. S3에서 받아온 원본 반환 +
             │                                 │   엣지에 사본 저장 (캐싱)
             ▼                                 ▼
       [ 빠른 응답 완료 ]                [ 다음 사용자는 Cache Hit]
```

1. 가까운 엣지 로케이션 도착
    
    클라이언트가 이미지/파일을 요청하면 위치상 가장 가까운 CloudFront 엣지 로케이션으로 다가간다.
    
2. 캐시 유효성 판단(Hit/Miss)
    - Cache Hit(적중) : 유효한 사본이 이미 있다면, S3로 가지 않고 엣지에서 즉시 사용자에게 응답
    - Cache Miss(비적중) : 사본이 없거나 만료되었다면, S3로 직접 가서 원본을 가져온다.
3. 사본 저장 및 응답
    
    Cache Miss 시 가져온 원본 데이터를 사용자에게 건네주는 동시에 해당 엣지 로케이션에 사본으로 저장한다. 이후 같은 지역의 다른 사용자는 바로 Cache Hit가 된다.
    

## 원본 보안 지키기 : OAC(Origin Access Control)

CloudFront를 세우더라도, 사용자가 S3버킷의 원본 URL 주소를 알아내서 S3로 직접 찌르면 CloudFront를 우회하게 된다.

해결책 : OAC

- S3버킷의 퍼블릭 액세스를 완벽히 차단하여 외부에서 직접 들어오는 길을 막는다.
- S3버킷 정책을 통해 ‘오직 지정된 CloudFront 배포를 통한 요청만 읽기를 허용한다’는 문을 열어준다.
- 결과적으로 사용자는 S3 주소로는 접근이 불가능하며, 오직 CloudFront 도메인을 통해서만 안전하게 컨텐츠를 받아볼 수 있게 된다.

## 정리

- 클라우드프론트는 객체를 사용자에게 전달하는 곳이다. S3는 객체를 저장하는 곳이고, 저장이랑 전달은 다른 개념이고 전달을 담당하는 걸 CDN에게 나눠줄 수 있따.
- 클라우드프론트가 특정 리전에 묶이지 않고 전 세계 엣지 로케이션에 걸쳐서 동작을 한다. origindls s3 버켓은 특정 리전 안에 있다. 요청 경로 생각하면 사용에서 엣지까지 그리고 엣지에서 리전 안에 origin까지 나눠볼 수 있다.
- 엣지에 유효한 사본이 있으면 거기서 바로 cache hit해서 반환을 하고, 만약에 없다면 오리진까지 가서 원본을 가져오고 사본을 남긴다.
