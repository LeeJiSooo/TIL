## 설명할 수 있어야 하는 것

- Image가 정확히 무엇인지
- 왜 이렇게 내용이 고정된 결과물을 따로 만드는지

## 도커 이미지의 정의

애플리케이션 실행에 필요한 모든 요소(코드, 런타임, 라이브러리, 설정 등)를 하나로 묶어둔 읽기 전용 스냅샷

- 스프링부트 : my-app.jar + Java Runtime(JDK/JRE 17)  + application.yml을 통째로 굳혀둔 결과물

1. 읽기 전용 : 한 번 빌드되어 만들어진 이미지는 절대로 변경되지 않는 불변 객체이다.
2. 스냅샷 : 특정 시점의 실행 환경 상태를 그대로 찍어서 굳혀둔 것
3. 탬플릿 : 이미지는 컨테이너를 생성하기 위한 설계도/템플릿이며, 하나의 이미지로 수십, 수백 개의 동일한 컨테이너를 복제하여 띄울 수 있다.

실행 형태 : 이미지는 그 자체로 메모리에 떠서 움직이는 프로세스가 아니며, 도커 데몬에 의해 실행되어야만 컨테이너라는 살아있는 프로세스가 된다.

## 이미지 레이어 구조와 CoW(Copy-on-Write)

도커 이미지는 하나의 거대한 파일이 아니라, 여러 읽기 전용 레이어가 층층히 쌓인 구조이다.

<img width="1212" height="1012" alt="image" src="https://github.com/user-attachments/assets/c732269b-7c1b-4733-9159-3d3a287226ba" />


```json
[ 컨테이너 실행 시 생성되는 얇은 쓰기 레이어 (Container Read-Write Layer) ]
─────────────────────────────────────────────────────────────
[ 레이어 3: Spring Boot application.jar (Read-Only)          ] ──┐
[ 레이어 2: Java 17 Runtime Environment (Read-Only)          ] ──┼─ 불변 이미지 레이어
[ 레이어 1: Base OS (Ubuntu / Alpine Linux) (Read-Only)       ]──┘ (여러 컨테이너가 공유)
```

1. 읽기 전용 레이어
- 도커파일에 적힌 한 줄 한 줄의 명령어가 빌드되면서 자기 몫의 레이어를 하나씩 쌓아 올린다.
- 재사용과 공간 절약 : 서로 다른 애플리케이션이라도 자바 17이라는 하위 레이어가 같다면, 이 레이어는 디스크에 단 1번만 저장되고 여러 이미지가 공동으로 공유/재사용한다. → 다운로드 속도 및 저장 공간 절약

1. 쓰기 전용 레이어(Container Read-Write Layer) & CoW
- 이미지(읽기 전용)를 바탕으로 컨테이너를 실행하는 순간, 맨 위에 아주 얇은 ‘쓰기 전용 레이어’가 얹혀진다.
- CoW(Copy-on-Write)동작 원리:
    - 컨테이너 실행 중에 파일이 수정되거나 새로 생성될 때, 원본 이미지 레이어를 직접 수정하지 않는다.
    - 수정이 필요한 원본 파일을 맨 위의 쓰기 레이어로 복사해온 뒤, 복사본을 수정한다.
        
        → 원본 이미지는 절대로 훼손되지 않고 안전하게 보존되며, 같은 이미지에서 뜬 여러 컨테이너들이 서로 간섭없이 독자적인 변경 사항을 유지할 수 있다.
        
- 휘발성 주의 : 컨테이너가 삭제되면 맨 위의 쓰기 레이어도 함께 증발한다. → 지속적으로 유지되어야 하는 데이터(DB 등)는 RDS, S3, 혹은 Docker Volume으로 외부에 영속 저장해야 한다.

## 이미지 식별자 : 이름, 태그, 다이제스트

이미지를 정확하게 구별하고 호출하기 위한 표기법

- 이름과 태그 : `nginx:latest` 또는 `my-spring-app:1.0.0` 처럼 `[이미지 이름]:[태그]` 조합으로 버전을 구분함 → 사람이 부여한 태그(latest 등)는 다른 이미지로 옮겨 붙여질 위험이 있다.
- 다이제스트  : 이미지 내용물 저체를 해시 알고리즘으로 계산한 고유한 식별 값
    - 이미지 내용이 단 1비티라도 바뀌면 다이제스트 값이 달라진다. → 서로 다른 환경에서 확인한 다이제스트 값이 같아면 동일한 이미지를 보장한다.

## 정리

- Image는 어플리케이션 실행에 필요한 코드랑 런타임 라이브러리 설정을 담아둔 읽기 전용 스냅샷이다. → 컨테이너 만들어내는 플랫폼
- 여러 단계 결과 거쳐서 만들어진 결과물이며 그 자체로는 실행중인 프로세스가 아니다.
- 구조 - 이미지는 여러 개의 읽기 전용 레이어로 이루어져 있고, 이미지로 컨테이너 실행하면 그 위에 얇은 쓰기 레이어 하나가 얹힌다.
- 실행중 변경은 쓰기 레이어에 기록 되고, 아래 원본 이미지 레이어 copy-on-write방식으로 안전하게 보존된다.
- 이미지는 읽기전용이고 불변인데 어디서든 실행 가능하게 하기 위한 측면에서 필요하고, 레이어로 되어 있는데 이미지가 공유하는 하위 레이어가 있다면 용량을 아끼고 전송량을 전략할 수 있다.
