## 설명할 수 있어야 하는 것

- 컨테이너 안의 데이터가 왜 사라지는가?
- 볼륨은 그 데이터를 어디에 어떻게 남기는가?
- 데이터를 컨테이너에 연결하는 방식에는 어떤 선택지가 있고 무엇이 다른가?

## Docker Volume & 데이터 영속성

#### 컨테이너 안의 데이터는 왜 지워지는가?

- 원인 : 컨테이너는 읽기 전용 이미지 레이어 위에 임시 쓰기 레이어를 얹어서 실행된다.
- 컨테이너 내부에서 생성/수정되는 모든 데이터(파일, DB레코드, 로그)는 이 임시 쓰기 레이어에만 쌓인다.
    
    → 컨테이너를 삭제(docker rm)하는 순간 임시 쓰기 레이어도 함께 사라지게되므로, 컨테이너의 수명과 데이터의 수명이 귀속된다.
    

#### Docker Volume이란?

컨테이너의 생명주기와 상관없이 데이터를 영구히 보존하고, 여러 컨테이너 간 데이터 공유를 가능하게 하기 위해 호스트파일 시스템에 생성되는 독립적인 전용 저장소이다.

동작원리(마운트 / Mount)

- 호스트 컴퓨터의 특정 저장 공간과 컨테이너 내부의 파일 경로를 서로 연결한다.
- 컨테이너 입장에서는 자기 내부 경로에 파일을 쓰는 것처럼 보이지만, 실제 데이터는 컨테이너 바깥인 호스트의 영구 디렉터리에 기록된다.

```
 ┌──────────────────────────────┐┌──────────────────────────────┐
 │         Container A          ││         Container B          │
 │  /home/volume (mount point)  ││  /home/volume (mount point)  │
 └───────────────┬──────────────┘└────────────────┬─────────────┘
                 │                                │
                 └───────────────┬────────────────┘
                                 │ mount
   ──────────────────────────────┼─────────────────────────────
               ┌─────────────────▼─────────────────┐
               │           Docker Volume           │
               │   /var/lib/docker/volumes/_data   │
               │             (영구 저장소)            │
               └───────────────────────────────────┘
   ───────────────────────────────────────────────────────────
                   ┌───────────────────────────┐
                   │      Host OS (Kernel)     │
                   └───────────────────────────┘
                   ┌───────────────────────────┐
                   │  Hardware · CPU/Mem/Disk  │
                   └───────────────────────────┘
```

볼륨이 주는 이점

1. 데이터 영속성 : 컨테이너를 삭제하고 동일한 이미지로 새 컨테이너를 띄워도, 볼륨을 다시 마운트하면 이전 데이터를 그대로 이어서 사용 가능하다.
2. 호스트 환경과의 격리(이름 기반 관리) : 개발자가 호스트의 복잡한 실제 파일 경로를 몰라도, 도커가 관리하는 ‘볼륨 이름’만 지정하면 어떤 서버에서든 동일하게 작동한다.
3. 컨테이너 간 데이터 공유 : 동일한 볼륨을 Container A와 Container B에 동시에 마운트하면, 두 컨테이너가 하나의 실제 저장 공간을 동시에 바라보며 데이터를 공유할 수 있다.

볼륨을 사용하는 사례

- 데이터베이스(EC2에 직접 DB컨테이너 띄울 때)
    - MySQL컨테이너 내부 데이터 경로를 도커 볼륨에 마운트하여 컨테이너가 재시작되도 DB데이터 유지
- 애플리케이션 로그 및 파일 보관
    - S3업로드 실패 시 임시 보관할 로컬 파일이나, 애플리케이션 실행 로그 축적
- 성능 최적화(캐시 & Warm-up데이터)
    - 컨테이너 재시작 시 JIT컴파일러 캐시나 애플리케이션 초기화 비용을 줄이기 위해 캐시 데이터를 볼륨에 남겨두고 재사용
- 컨테이너 간 협업
    - 한 컨테이너가 만들어둔 결과 파일이나 로그를 다른 컨테이너가 읽어서 처리할 때

## 컨테이너 데이터 연결 방식 비교(Volume, Bind Mount, tmpfs Mount)

도커에서 데이터를 연결/유지하는 방식은 목적에 따라서 3가지가 존재한다.

<img width="1044" height="560" alt="image" src="https://github.com/user-attachments/assets/7cdf3888-a10d-45ae-b684-bd35515f5e78" />


```
[ 호스트 컴퓨터 메모리 / 디스크 구조 ]

 ┌──────────────────────────────────────────────────┐
 │                      RAM                         │
 │ ┌──────────────────────────────────────────────┐ │
 │ │                tmpfs Mount                   │ │ ──► 휘발성 (메모리에 저장, 속도 극대화)
 │ └──────────────────────────────────────────────┘ │
 └──────────────────────────────────────────────────┘
 ┌──────────────────────────────────────────────────┐
 │                  Host Disk                       │
 │ ┌──────────────────────┐┌──────────────────────┐ │
 │ │    Docker Volume     ││     Bind Mount       │ │
 │ │ (/var/lib/docker/..) ││ (/home/user/app/..)  │ │
 │ └──────────────────────┘└──────────────────────┘ │
 └──────────────────────────────────────────────────┘
             ▲                         ▲
             │                         │
     도커가 전용 영역 관리       개발자가 직접 경로 지정
```

| **구분** | **Volume (도커 볼륨)** | **Bind Mount (바인드 마운트)** | **tmpfs Mount** |
| --- | --- | --- | --- |
| **저장 위치** | 호스트 디스크 내 **도커 전용 관리 영역** (`/var/lib/docker/volumes/`) | **호스트 디스크의 임의 디렉터리** (개발자가 직접 경로 지정) | **호스트의 RAM (메모리)** |
| **관리 주체** | **도커 엔진 (Docker)** | **사용자 / 호스트 OS** | **호스트 시스템 메모리** |
| **수명** | 컨테이너와 무관하게 **영구 보존** | 컨테이너와 무관하게 **영구 보존** | **컨테이너 종료 시 즉시 삭제** |
| **주요 사용처** | **운영 환경 (Production)**, DB 데이터, 영구 보관 파일 | **개발 환경 (Local Dev)**, 로컬 코드를 컨테이너에 즉시 반영할 때 | 보안이 중요한 **임시 데이터**, 극상의 속도가 필요한 캐시 |
- Volume : 운영 환경 표준. 호스트 시스템의 파일 구조에 의존하지 않고 안전하게 데이터를 보관
- Bind Mount : 개발 환경 표준. 내 맥북/PC의 프로젝트 폴더를 컨테이너에 그대로 꽂아서, 코드를 수정하면 컨테이너 안에서도 즉시 반영되게 만들 때 주로 사용함
- tmpfs Mount : 보안상 디스크에 남으면 안 되는 비밀번호/암호화 키나, 메모리 연산 속도가 필요한 작업에 사용

## 정리

- 컨테이너 실행중에 생긴 데이터는 쓰기 레이어에 들어가고 컨테이너 지우면 사라진다. → 실행 단위의 수명이랑 데이터의 수명이 묶여있다.
- 볼륨은 이런 묶음을 분리해낸다. 데이터를 컨테이너 안이 아니라, 호스트 파일 시스템 위의 도커가 관리하는 별도 저장소에 둔다.
- 컨테이너는 마운트를 통해서 자기 내부 경로에서 이 저장소에 접근하지만 실제 데이터는 컨테이너 바깥의 호스트에 남는다.
- 그래서 컨테이너 지우거나 다시 띄워도 데이터 그대로 유지되고 같은 볼륨은 여러 컨테이너에 연결하면 데이터를 공유할 수 있다.
- 데이터 연결하는 방식이 볼륨 하나가 아니라 다른 방식들도 있는데 결국 볼륨을 사용한다.
